# Research Source Registry

Use this registry as a starting point for fast research. Prefer primary sources
first, then use secondary sources to understand adoption, sentiment, or
competitive positioning.

## Technical sources

| Topic | Primary sources | Use for |
| --- | --- | --- |
| Node.js versions | [Node.js releases](https://nodejs.org/en/about/previous-releases), [nodejs/release schedule](https://github.com/nodejs/release#release-schedule) | Current, LTS, maintenance, and EOL status. |
| React | [React blog](https://react.dev/blog), [React changelog](https://github.com/facebook/react/blob/main/CHANGELOG.md), [React releases](https://github.com/facebook/react/releases) | Release notes, breaking changes, security notices, and feature status. |
| Next.js | [Next.js docs](https://nextjs.org/docs), [Next.js blog](https://nextjs.org/blog), [vercel/next.js releases](https://github.com/vercel/next.js/releases) | Framework capabilities, router behavior, release changes, and migration notes. |
| Prisma | [Prisma docs](https://www.prisma.io/docs), [Prisma releases](https://github.com/prisma/prisma/releases), [Prisma pricing](https://www.prisma.io/pricing) | ORM features, database support, migration behavior, and hosted product pricing. |
| Drizzle | [Drizzle docs](https://orm.drizzle.team/docs/overview), [drizzle-orm releases](https://github.com/drizzle-team/drizzle-orm/releases) | ORM architecture, SQL-like API, supported databases, and release changes. |

## Product and market sources

| Need | Sources | Notes |
| --- | --- | --- |
| Demand signals | [Google Trends](https://trends.google.com/trends/), [Hacker News search](https://hn.algolia.com/), Reddit search, community Discords/Slack groups | Treat these as directional unless backed by volume or repeated examples. |
| Competitors | Product websites, pricing pages, [G2](https://www.g2.com/), [Capterra](https://www.capterra.com/), [AlternativeTo](https://alternativeto.net/), [Product Hunt](https://www.producthunt.com/) | Verify claims on the vendor site before citing them as facts. |
| Funding and company signals | Company blogs, press pages, public filings, [Crunchbase](https://www.crunchbase.com/) | Many databases have incomplete free access; mark gaps clearly. |
| User language | Reddit threads, Hacker News comments, app reviews, GitHub issues, support forums | Useful for pain points and wording; not enough for market size by itself. |

## Citation rules

- Include the source name and URL for every factual claim.
- Add the access date when the source is pricing, version, or trend data.
- Prefer exact vendor pricing pages over blog posts that mention pricing.
- Mark source confidence as low when the source is old, indirect, paywalled, or anecdotal.
- Do not cite this registry as evidence; cite the underlying source.
