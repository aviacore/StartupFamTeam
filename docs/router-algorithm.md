# Алгоритм роутера

## Участники

- **CEO (фаза 1)** — дробит задачу на подзадачи, передаёт PM, отключается
- **CEO (фаза 2)** — подключается после всех агентов, собирает результаты в итоговый ответ
- **PM** — передаёт подзадачи роутеру, контролирует выполнение агентами промежуточных этапов
- **Роутер** (встроенный в сервер) — назначает агентов и провайдеров по правилам

## Порядок работы

1. CEO получает задачу, разбивает на подзадачи, передаёт PM, отключается
2. PM по каждой подзадаче запрашивает роутер: какие агенты и провайдеры нужны
3. Роутер работает по правилам из этого файла
4. PM запускает выполнение, контролирует результат каждого агента
5. Если агент вернул ошибку — PM решает: перезапустить или пропустить
6. После выполнения всех агентов CEO подключается снова — формирует итоговый ответ

## Алгоритм назначения провайдера

Для каждой подзадачи роутер последовательно:

1. Определяет тип подзадачи (анализ, код, дизайн, стратегия, тесты, маркетинг)
2. Применяет правила исключения — убирает провайдеров, которые не подходят для этого типа
3. Сортирует оставшихся провайдеров по приоритету:
   - free unlimited (без лимитов, например DeepSeek V4 Flash)
   - free limited (с лимитами, например Gemini, GitHub Models, Mistral, OpenRouter)
   - paid (платные, например OpenAI, Anthropic, xAI)
4. Назначает провайдера с наивысшим приоритетом, который ещё не занят в этом запуске (для параллельности)
5. Если все провайдеры заняты — берёт из свободных, потом из paid

## Правила исключения (конфиг)

Исключение — основной механизм. Если провайдер не исключён — он может быть назначен.

## Параллельность

- Каждому агенту назначается свой провайдер (agents_count <= providers_count)
- Если провайдеров меньше чем агентов — некоторые агенты делят провайдера (выполняются последовательно)
- Агенты без зависимостей выполняются параллельно
- CEO (фаза 2) выполняется последним, после всех

## Динамическое назначение провайдеров

Провайдер закрепляется за агентом **только на время одного исполнения**:

- При каждом запуске агента роутер заново выбирает провайдера по текущим правилам
- В следующий запуск тому же агенту может достаться другой провайдер
- Это позволяет учитывать актуальную доступность, квоты и нагрузку

### По времени и загруженности

**Сам роутер не делает AI-вызов для перебора.** Назначение провайдера — это правила (исключения + приоритеты + занятость), которые выполняются как обычный код (миллисекунды). Никаких API-запросов.

AI внутри роутера нужен только на этапе **анализа задачи** (если ключевых слов не хватило для определения типа). Это один короткий запрос в начале пайплайна.

### Чем питается роутер

Роутер использует **DeepSeek V4 Flash** (free unlimited, без лимитов) — только если требуется AI для анализа задачи. Перебор провайдеров и назначение — чистая логика, без затрат.
