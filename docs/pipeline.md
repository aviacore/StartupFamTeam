# Pipeline — алгоритм выполнения задачи

## Фазы

```
[IDLE] → [ANALYSIS] → [ROUTING] → [EXECUTION] → [SYNTHESIS] → [DONE]
                ↓            ↓           ↓             ↓
            CEO (1)      Router      PM + Agents   CEO (2)
```

### IDLE
- Сервер запущен, ждёт задачу
- status: `idle`

### ANALYSIS (CEO фаза 1)
1. Ассистент читает `task.txt`
2. Запрашивает CEO: разбить задачу на подзадачи
3. CEO возвращает список: `[{id, description, agent_type, depends_on}, ...]`
4. Запись в `state.json`: `phase: "analysis"`, `subtasks: [...]`
5. CEO отключается

Провайдер CEO — выбирается роутером по общим правилам (приоритет — бесплатные без лимита).

### ROUTING (Router)
1. PM передаёт подзадачи роутеру
2. Роутер на каждую подзадачу:
   - Определяет нужного агента (по типу из подзадачи)
   - Исключает неподходящих провайдеров (правила из конфига)
   - Сортирует оставшихся по приоритету
   - **Не закрепляет провайдера** — только список кандидатов
3. Роутер также проверяет зависимости между подзадачами
4. Результат: `routing.json` с графом выполнения
5. PM получает план: кто за кем, кто параллельно

Провайдер роутера — DeepSeek V4 Flash (free unlimited, только если не хватило ключевых слов для определения типа подзадачи).

### EXECUTION (PM + Agents)
1. PM разворачивает граф в порядок выполнения:
   - Level 0: подзадачи без зависимостей (параллельно)
   - Level N: подзадачи, чьи зависимости выполнены
2. Для каждого агента перед запуском:
   - Роутер выбирает провайдера из списка кандидатов
   - Учитывает: занятость сейчас, результат последнего теста (health), квоты
3. Агент выполняет подзадачу:
   - Получает: контекст (результаты предыдущих агентов, если depends_on), описание подзадачи
   - Возвращает: результат (текст) + статус (ok/error)
4. Если ошибка:
   - PM проверяет тип ошибки (таймаут / квота / биллинг / неизвестно)
   - Решает: retry тем же провайдером / retry другим провайдером / skip
   - Если retry — возврат к шагу 2 для этого агента
   - Если skip — подзадача помечается как `skipped`, downstream-зависимости тоже skip
5. Каждый результат пишется в `project/results/` по ID подзадачи
6. После каждого уровня графа PM проверяет, все ли done/skipped

Провайдеры для агентов — динамические, выбираются при каждом запуске.

### SYNTHESIS (CEO фаза 2)
1. Все подзадачи выполнены (done или skipped)
2. PM собирает контекст: исходная задача, все результаты подзадач, лог ошибок
3. Запрашивает CEO: сформировать итоговый ответ
4. CEO возвращает финальный результат
5. Запись в `state.json`, в `project/result.md`

Провайдер CEO — выбирается роутером как обычно.

### DONE
- status: `done`
- Результат доступен в `project/result.md`
- Дашборд показывает Done

## Граф выполнения (пример)

Задача: «Сделать лендинг для стартапа»

### Подзадачи от CEO:
```
1. designer: дизайн лендинга
2. developer: вёрстка лендинга (depends_on: 1)
3. marketer: текст для лендинга
```

### Routing:
```
4. designer → (deepseek, gemini, openrouter) — параллельно с 5
5. marketer → (deepseek, openai, anthropic)
6. developer → (github, openai) — после 4
```

### Execution (уровни):
```
Level 0: [designer, marketer]     — параллельно
Level 1: [developer]              — после designer
Level 2: [ceo]                    — synthesis, после всех
```

## Обработка ошибок

| Проблема | Действие |
|----------|----------|
| Provider timeout | Retry другим провайдером |
| Provider quota exceeded | Retry другим провайдером (или помечаем как exhausted) |
| Provider billing required | Исключаем на этот запуск |
| Agent returned nonsense | PM решает: можно retry с другим провайдером |
| Agent data corrupted | Retry тем же провайдером |
| Provider free limit reached | Retry следующим по приоритету |

Если retry исчерпан (все провайдеры перебраны) — подзадача `skipped`.

## State-машина

```
idle → received → analyzing → routed → executing → synthesizing → done
                  ↓                                       ↓
              error (CEO fail)                       error (CEO fail)
                  ↓                                       ↓
               idle                                    idle
```

`synthesis_error`: CEO не смог собрать итог. Результаты подзадач сохранены, но финала нет. Можно retry synthesis.
