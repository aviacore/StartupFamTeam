# PM — Output

Как PM, я проанализировал работу CEO и вижу, что базовая задача выполнена — названия агентов переведены на русский язык. Однако для product-менеджмента этого недостаточно. Чтобы задача стала полноценной и полезной для команды, я предлагаю декомпозировать её на конкретные подзадачи с чёткими критериями приёмки, приоритетами и спринтами.

Ниже — готовая спецификация в формате `project/tasks.md`.

---

## project/tasks.md

### Задача 1. Сбор ответов от всех агентов
**Описание:**  
Запросить у каждого агента (Ideation, Strategy, Business Model, Pitch) письменное название его должности/скилла на русском языке. Убедиться, что ответ получен от каждого.

**Критерии приёмки:**  
- Получены ответы от 4 агентов.  
- Каждый ответ зафиксирован в текстовом виде.  
- Если агент не ответил в течение 24 часов — инициировать повторный запрос.

**Приоритет:** P0 (блокирует дальнейшие шаги)

---

### Задача 2. Сводка ответов в единый файл
**Описание:**  
На основе собранных ответов сформировать файл `Plan_06.md` в папке проекта. Включить таблицу с колонками: «Агент (англ. навык)», «Название на русском языке (основное)», «Вариант (синоним)».

**Критерии приёмки:**  
- Файл `Plan_06.md` создан и размещён в корне проекта.  
- Таблица содержит данные по всем 4 агентам.  
- Формат файла — Markdown.  
- Файл открывается и читается корректно.

**Приоритет:** P1 (необходимо для завершения базовой задачи)

---

### Задача 3. Согласование названий с командой
**Описание:**  
После создания `Plan_06.md` провести короткое голосование или опрос среди агентов (или stakeholders) для утверждения финальных русскоязычных названий. Цель — избежать путаницы в будущих коммуникациях.

**Критерии приёмки:**  
- Каждое название подтверждено не менее чем 2 голосами.  
- В файл добавлена секция «Согласовано» с датой и подписями.  
- При конфликте названий — зафиксировать спорный момент и передать CEO для решения.

**Приоритет:** P2 (повышает качество, но не блокирует)

---

### Задача 4. Документирование процесса для повторяемости
**Описание:**  
Описать в `project/process.md` алгоритм, по которому CEO запрашивает названия у агентов, чтобы в будущем можно было быстро повторить процедуру для новых участников команды.

**Критерии приёмки:**  
- В `project/process.md` описаны шаги: запрос → ожидание → фиксация → сводка → согласование.  
- Указаны сроки на каждый шаг.  
- Пример вызова агента (шаблон запроса) включён.

**Приоритет:** P2 (важно для масштабирования)

---

### Задача 5. Автоматизация генерации файла Plan_06
**Описание:**  
Написать скрипт (bash или Python), который при наличии ответов от агентов (например, в виде JSON или отдельных .txt) автоматически формирует `Plan_06.md`. Скрипт должен проверять наличие всех необходимых полей.

**Критерии приёмки:**  
- Скрипт запускается одной командой.  
- На выходе — корректный `Plan_06.md`.  
- Если данных не хватает — скрипт выдаёт ошибку с указанием отсутствующего агента.  
- Скрипт размещён в `project/scripts/generate_plan_06.sh` (или `.py`).

**Приоритет:** P3 (улучшение, не критично для MVP)

---

### Итоговый план спринтов

| Спринт | Задачи                          | Приоритеты |
|--------|---------------------------------|------------|
| 1      | Задача 1 (сбор ответов)         | P0         |
| 1      | Задача 2 (создание Plan_06.md)  | P1         |
| 2      | Задача 3 (согласование)         | P2         |
| 2      | Задача 4 (документирование)     | P2         |
| 3      | Задача 5 (автоматизация)        | P3         |

---

Этот набор задач позволяет не просто выполнить разовую просьбу CEO, но и создать процесс, который будет работать на будущее. Готов передать в `project/plan.md` как часть общего плана.
