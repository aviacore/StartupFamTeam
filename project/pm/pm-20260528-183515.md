# Задачи для WEB-приложения управления AI-провайдерами

## Задача 1: Настройка проекта и базовая архитектура (P0)

**Описание:**
Создать каркас WEB-приложения с использованием современного стека технологий (React + TypeScript + Next.js или Vite). Настроить маршрутизацию, базовые компоненты и стили.

**Критерии приёмки:**
- [ ] Инициализирован проект с выбранным стеком
- [ ] Настроен Tailwind CSS для современного дизайна
- [ ] Создана базовая структура папок (components, pages, services, types)
- [ ] Настроена маршрутизация (главная страница, страница провайдеров)
- [ ] Подключены необходимые зависимости (react-router-dom, axios, react-hook-form)
- [ ] Проект запускается и отображает стартовую страницу

---

## Задача 2: Разработка UI-компонентов (P0)

**Описание:**
Создать набор переиспользуемых UI-компонентов в современном минималистичном дизайне.

**Компоненты:**
- Card — карточка провайдера
- Button — кнопка с вариантами (primary, secondary, danger)
- Input — поле ввода с отображением/скрытием пароля
- Modal — модальное окно для добавления/редактирования
- Table — таблица для списка провайдеров
- Badge — значок статуса
- SearchBar — поисковая строка

**Критерии приёмки:**
- [ ] Все компоненты типизированы на TypeScript
- [ ] Компоненты адаптивны (responsive)
- [ ] Использованы градиенты, тени, плавные анимации
- [ ] Компоненты доступны через Storybook или отдельную страницу документации

## Задача 3: Модель данных и типизация (P0)

**Описание:**
Определить TypeScript-типы и интерфейсы для данных приложения.

**Типы:**
```typescript
interface Provider {
  id: string;
  name: string;
  model: string;
  website: string;
  apiKey: string;
  balance: number;
  createdAt: string;
  updatedAt: string;
  isActive: boolean;
}

type ProviderFormData = Omit<Provider, 'id' | 'createdAt' | 'updatedAt'>;
```

**Критерии приёмки:**
- [ ] Создан файл types/index.ts
- [ ] Определены все необходимые интерфейсы
- [ ] Добавлены enum для типов провайдеров (OpenAI, Anthropic, Google и т.д.)

## Задача 5: Основная страница со списком провайдеров (P0)

**Описание:**
Разработать главную страницу приложения с таблицей/карточками всех добавленных провайдеров.

**Функциональность:**
- Отображение всех провайдеров в виде карточек или таблицы
- Поиск по названию провайдера
- Фильтрация по модели
- Сортировка по дате добавления, балансу, имени
- Индикация активных/неактивных провайдеров
- Кнопка "Добавить провайдера"

**Критерии приёмки:**
- [ ] Страница загружается с существующими данными
- [ ] Поиск работает в реальном времени (debounce 300ms)
- [ ] Сортировка работает по клику на заголовок столбца
- [ ] Адаптивный дизайн (столбцы скрываются на мобильных)

## Задача 6: Форма добавления/редактирования провайдера (P0)

**Описание:**
Создать модальное окно с формой для добавления нового или редактирования существующего провайдера.

**Поля формы:**
- Название провайдера (текстовое поле, обязательное)
- Модель (выпадающий список, обязательное)
- Адрес сайта (URL, валидация)
- API-ключ (поле с маскировкой, обязательное)
- Остаток денег (числовое поле, 0 по умолчанию)

**Валидация:**
- Название: от 2 до 100 символов
- URL: валидный URL
- API-ключ: не пустой
- Баланс: число >= 0

**Критерии приёмки:**
- [ ] Форма открывается по кнопке "Добавить" или "Редактировать"
- [ ] Валидация на стороне клиента с сообщениями об ошибках
- [ ] При редактировании поля заполнены текущими значениями
- [ ] API-ключ отображается/скрывается по кнопке (глазик)
- [ ] При успешном сохранении модальное окно закрывается

## Задача 7: Управление API-ключами (P1)

**Описание:**
Реализовать безопасное хранение и отображение API-ключей.

**Требования:**
- Ключи хранятся в зашифрованном виде (localStorage с шифрованием)
- Возможность скопировать ключ в буфер обмена
- Возможность обновить ключ без изменения других полей
- Подтверждение перед удалением ключа

**Критерии приёмки:**
- [ ] Ключи не отображаются открыто в интерфейсе
- [ ] Копирование работает с уведомлением "Скопировано"
- [ ] Добавлена кнопка "Обновить ключ" в карточке провайдера
- [ ] При удалении ключа запрос подтверждения (confirm)

---

## Задача 8: Отслеживание баланса (P1)

**Описание:**
Реализовать функционал управления и отображения остатка денег для каждого провайдера.

**Функциональность:**
- Отображение баланса с форматированием (разделители тысяч, $)
- Возможность пополнить/обновить баланс
- Индикация низкого баланса (< $10) — красный цвет
- Возможность удалить провайдера при нулевом балансе
- История изменений баланса (опционально)

**Критерии приёмки:**
- [ ] Баланс отображается в красивом формате (например, $1,234.56)
- [ ] При балансе < $10 появляется предупреждение (иконка/цвет)
- [ ] Кнопка "Пополнить" открывает модалку с вводом суммы
- [ ] Изменения баланса сохраняются в localStorage

## Задача 9: Локальное хранение данных (P1)

**Описание:**
Реализовать сохранение всех данных в localStorage с возможностью экспорта/импорта.

**Требования:**
- Все провайдеры сохраняются при перезагрузке
- Экспорт данных в JSON-файл
- Импорт данных из JSON-файла
- Индикация последнего обновления

**Критерии приёмки:**
- [ ] Данные не теряются при перезагрузке страницы
- [ ] Кнопка "Экспорт" скачивает файл providers.json
- [ ] Кнопка "Импорт" позволяет выбрать файл и загрузить данные
- [ ] При импорте данные заменяются или объединяются (выбор)
- [ ] Отображается дата последнего изменения

## Задача 10: Анимации и микро-взаимодействия (P2)

**Описание:**
Добавить плавные анимации и визуальные эффекты для улучшения UX.

**Анимации:**
- Появление карточек с задержкой (fade-in)

- [ ] Все анимации длительностью 200-400ms
- [ ] Глаз не режет, анимации ненавязчивы
- [ ] Скелетон отображается 1-2 секунды при первой загрузке

## Задача 11: Тёмная тема (P2)

**Описание:**
Реализовать переключение между светлой и тёмной темой с сохранением выбора.

**Требования:**
- Переключение через кнопку в хедере
- Сохранение выбора в localStorage
- Иконка солнца/луны для текущей темы
- Все компоненты адаптированы под обе темы

**Критерии приёмки:**
- [ ] Тёмная тема применена ко всем компонентам
- [ ] Переключение происходит мгновенно
- [ ] Выбор сохраняется после перезагрузки
- [ ] Контрастность соответствует WCAG AA

## Задача 12: Адаптивный дизайн (P1)

**Описание:**
Обеспечить корректное отображение на всех устройствах (мобильные, планшеты, десктоп).

**Требования:**
- Mobile-first подход
- Breakpoints: 640px, 768px, 1024px, 1280px
- На мобильных — карточки вместо таблицы
- На десктопе — таблица с колонками
- Touch-friendly кнопки (мин 44x44px)

**Критерии приёмки:**
- [ ] Приложение корректно отображается на всех разрешениях
- [ ] На мобильных: прокрутка, если контент не помещается
- [ ] Хедер адаптируется (гамбургер-меню на мобильных)
- [ ] Формы масштабируются под экран
