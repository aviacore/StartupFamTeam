# PM — craftstack.html Ниже — разбивка на задачи для доработки лендинга `craftstack.html` в рамках проекта. Формат соответствует PM-документации: каждая задача содержит заголовок, описание, критерии приёмки и приоритет. --- ### Задача 1: Архивация текущего лендинга **Описание:** Переименовать существующий файл `project/landing/craftstack.html` в `project/landing/craftstack_v1.html` для сохранения истории. Убедиться, что все ссылки и ресурсы внутри файла остаются валидными после переименования (если используются относительные пути, они не должны сломаться). **Критерии приёмки:** - Файл успешно переименован и открывается без ошибок. - В консоли браузера нет ошибок 404 (если использовались относительные ссылки). **Приоритет:** P0 --- ### Задача 2: Изучение новых возможностей CraftStack и составление списка изменений **Описание:** Проанализировать документацию/релизные ноты CraftStack (предполагается, что они доступны в папке `project/docs/` или в репозитории). Составить список новых функций, которые должны быть отражены на лендинге (например: новый модуль AI-ассистента, интеграция с внешними сервисами, обновлённый UI-кит, расширенная аналитика). Список прикрепить к этой задаче в виде комментария или отдельного файла `new_features_list.md`. **Критерии приёмки:** - Список содержит не менее 3 ключевых новых возможностей. - Каждая возможность кратко описана (1-2 предложения). **Приоритет:** P1 --- ### Задача 3: Разработка обновлённого контента для лендинга **Описание:** На основе списка новых функций подготовить текстовые блоки для замены или дополнения секций лендинга: - Обновить заголовки и подзаголовки (Hero section). - Добавить/заменить карточки функций (возможно, добавить новую строку карточек). - Обновить секцию «Преимущества» (если была). - Подготовить призывы к действию (CTA), соответствующие новым возможностям. Тексты должны быть краткими, маркетингово-ориентированными. **Критерии приёмки:** - Готовый файл `content_v2.md` с текстами для каждой секции. - Тексты проходят проверку на орфографию и соответствуют тону бренда. **Приоритет:** P1 --- ### Задача 4: Вёрстка обновлённого лендинга **Описание:** Создать новый файл `project/landing/craftstack.html` на основе дизайна текущей версии (`craftstack_v1.html`), но с заменой/добавлением контента из `content_v2.md`. Верстка должна быть адаптивной, все стили и скрипты остаются в том же формате (возможно, потребуется добавить новые CSS-классы для новых элементов). Цветовая схема, шрифты, общие компоненты (header, footer, кнопки) не меняются. **Критерии приёмки:** - Файл открывается в последних версиях Chrome, Firefox, Safari. - Все новые блоки отображаются корректно на desktop и mobile (проверить breakpoints). - Нет битых путей к изображениям или скриптам. - Стиль полностью совпадает с исходным (проверить по пикселям для ключевых элементов). **Приоритет:** P0 --- ### Задача 5: Тестирование нового лендинга на соответствие критериям доступности (a11y) **Описание:** Провести базовое тестирование на доступность: - Все изображения имеют alt-тексты. - Контрастность текста на фонах не ниже 4.5:1. - Интерактивные элементы доступны с клавиатуры. - Семантическая структура (h1→h2→h3) соблюдена. Если обнаружены нарушения — исправить. **Критерии приёмки:** - Lighthouse Accessibility score не ниже 90. - Нет ошибок навигации с клавиатуры. **Приоритет:** P2 --- ### Задача 6: Финальное ревью и утверждение изменений **Описание:** Провести код-ревью с командой (PM, дизайнер, разработчик). Убедиться, что все задачи выполнены, файлы сохранены, нет регрессии в старых функциях (если какие-то секции были удалены — не затронуты ссылки из других страниц). После утверждения — закоммитить и смержить в ветку `main` (или `landing-update`). **Критерии приёмки:** - Все вышеперечисленные задачи имеют статус «Done». - Отсутствуют замечания от участников ревью. - Код в репозитории обновлён. **Приоритет:** P0 --- Если нужен сам файл `project/tasks.md` в полном формате — я могу сгенерировать его отдельно.
