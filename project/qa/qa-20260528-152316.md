### 1. Аудит кода Developer и CTO: найденные баги и уязвимости

Я провёл статический анализ и выявил **4 критических дефекта**, которые могут нарушить работу системы.

#### Баг №1: Некорректная обработка дубликатов в API
**Где:** `project/api/routes/agents.js` (POST /response)
**Описание:**  
При отправке повторного POST-запроса с тем же агентом (например, второй раз для "Ideation") сервер **не проверяет, существует ли уже запись**. В результате в `agent_responses.json` появляются дубликаты, а при генерации Plan_06.md — задвоенные строки.
**Воспроизведение:**  
```bash
# Отправить дважды
curl -X POST http://localhost:3000/api/agents/response -H "Content-Type: application/json" -d '{"agent":"Ideation","russian_title":"Генерация идей"}'
curl -X POST http://localhost:3000/api/agents/response -H "Content-Type: application/json" -d '{"agent":"Ideation","russian_title":"Генерация идей"}'
```
**Результат:** В JSON два одинаковых объекта, в Markdown — две строки Ideation.
**Ожидаемое поведение:** Сервер должен возвращать ошибку `409 Conflict` с сообщением "Ответ для этого агента уже существует" или обновлять существующую запись (PATCH).

**Фикс:**
```javascript
// routes/agents.js — перед сохранением
const existingIndex = data.findIndex(item => item.agent === req.body.agent);
if (existingIndex !== -1) {
  return res.status(409).json({ error: 'Ответ для этого агента уже существует. Используйте PUT для обновления.' });
}
```

#### Баг №2: Отсутствие валидации на SQL-инъекции в CLI-скрипте
**Где:** `project/scripts/ceo_collect.sh`
**Описание:**  
Скрипт напрямую вставляет пользовательский ввод (`russian_title`, `synonym`) в JSON-строку без экранирования. Если CEO введёт что-то вроде `"` или `\`, JSON станет невалидным. При использовании `jq` (альтернатива sed) — уязвимости нет, но в скрипте используется `sed`, что небезопасно.
**Воспроизведение:**  
Запустить `ceo_collect.sh` и ввести для поля "Название на русском": `A"B` — JSON сломается.
**Ожидаемое поведение:** Скрипт должен экранировать кавычки или использовать `jq` для корректного формирования JSON.

**Фикс (использовать `jq` вместо ручной сборки):**
```bash
entry=$(jq -n \
  --arg agent "$agent" \
  --arg eng "$agent" \
  --arg rus "$russian_title" \
  --arg syn "$synonym" \
  '{agent: $agent, english_skill: $eng, russian_title: $rus, synonym: $syn, timestamp: now | todate}')
```

#### Баг №3: Лендинг Marketer не работает без сервера (CORS-проблема)
**Где:** `project/landing/index.html` (Marketer)
**Описание:**  
Лендинг собирает email через `fetch` или форму, но **не указан endpoint для отправки данных**. В коде есть поле ввода email, но нет JavaScript-обработчика. Если просто открыть `index.html` в браузере (file://), форма не сработает. Даже если лендинг будет на GitHub Pages, а API — на локальном сервере, возникнет CORS-ошибка.
**Ожидаемое поведение:**  
- Добавить обработчик формы с POST-запросом на `/api/subscribe`.
- В API сервера Developer добавить CORS-заголовки.

**Фикс (добавить в server.js Developer):**
```javascript
// CORS middleware
app.use((req, res, next) => {
  res.header('Access-Control-Allow-Origin', '*');
  res.header('Access-Control-Allow-Methods', 'GET, POST, PUT, DELETE');
  res.header('Access-Control-Allow-Headers', 'Content-Type');
  next();
});
```

#### Баг №4: Отсутствует обработка ошибок при чтении JSON-файла
**Где:** `project/api/middleware/validator.js` (Developer)
**Описание:**  
Если файл `agent_responses.json` повреждён (например, ручное редактирование с ошибкой синтаксиса), функция `loadData()` выбросит необработанное исключение, и сервер упадёт с `500 Internal Server Error`. Ни в одном модуле нет `try...catch`.
**Воспроизведение:**  
Открыть `agent_responses.json`, удалить запятую между объектами → обновить дашборд.
**Ожидаемое поведение:** Сервер должен возвращать `500` с осмысленным сообщением об ошибке, но не падать полностью.

**Фикс:**
```javascript
function loadData() {
  try {
    if (!fs.existsSync(DATA_FILE)) {
      fs.writeFileSync(DATA_FILE, JSON.stringify([], null, 2));
    }
    const raw = fs.readFileSync(DATA_FILE, 'utf8');
    return JSON.parse(raw);
  } catch (err) {
    console.error('Ошибка чтения данных:', err.message);
    return []; // возвращаем пустой массив, не падаем
  }
}
```
